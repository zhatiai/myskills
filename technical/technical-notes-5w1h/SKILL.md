# 5W1H 技术笔记

把技术材料整理成少而有用、可复习、可迁移的中文 Markdown 笔记。目标是保留正确理解和工程判断所需的最小充分知识，而不是缩写原文或填满固定模板。

## 核心原则

1. 先识别用户真正要理解的问题，再组织内容。
2. 优先保留定义、机制、因果、边界和工程权衡。
3. P0 核心知识必须保留；P1 只保留与用户目标相关的部分；P2 默认删除。
4. 5W1H 是完整性检查框架，不是固定目录；没有信息价值的维度不输出。
5. 事实、推论和建议不得混淆；不确定内容应降低判断强度或标记待验证。
6. 删除重复、主持句、空评价、弱相关背景和无助于理解的例子。
7. 用户的格式、深度、资料范围和受众要求优先。

## 适用边界

使用本 Skill：

- 整理技术概念、机制、架构、协议、源码原理或工程知识。
- 从文章、官方文档、RFC、源码或用户材料中提炼长期笔记。
- 用户要求 5W1H、提炼重点、去掉废话或整理成 Markdown。

默认不使用：

- 目标是解决当前故障、执行命令、修改代码或修复 Bug。
- 目标是 API 字段字典、会议纪要、营销文案、翻译或普通摘要。
- 用户只需要一个很短的直接答案。

多个 Skill 都可能适用时，以最终产物判断：长期复习的技术知识使用本 Skill；故障、源码调查或架构决策先由对应工作流完成，本 Skill 只负责最终知识整理。

## 工作流

1. 明确主题、读者、使用目标、期望深度和可用资料。缺失信息不影响质量时直接采用合理默认值。
2. 提取对象、关系、机制、因果、状态、边界、权衡和例外，先建立知识主干。
3. 按 P0/P1/P2 筛选信息。删除某条内容会造成概念错误、因果断裂、条件缺失或决策失真时，才优先保留。
4. 用 `问题 → 约束 → 机制 → 结果` 组织核心因果链；机制型主题还应说明输入、处理者、状态、触发条件和输出。
5. 将已有知识映射到 What / Why / How / Where / When / Who，再决定实际章节；不要先建六个空标题。
6. 仅在影响理解或决策时补充 Trade-offs、Alternatives、Failure Modes、Real World 或最小示例。
7. 输出中文 Markdown，并做一次简短审计：必要、无重复、术语稳定、结论有依据、边界未丢失。

## 5W1H 最小定义

- **What**：定义、核心对象和概念边界。
- **Why**：原问题、约束、设计动机和改善结果。
- **How**：流程、状态变化、关键机制和失败路径。
- **Where**：系统层次、调用链位置及上下游关系。
- **When**：适用条件、不适用情况、退化点和版本边界。
- **Who**：参与者、控制者、所有者、权限或责任主体；主体关系不重要时省略。

用户明确要求固定 5W1H 格式时可以保留全部标题，但不得编造内容；无独立价值的维度应简短说明不展开。

## 深度调整

- **速查 / 只要重点**：仅输出 P0 和最多一个必要示例。
- **详细 / 深入原理**：输出 P0 与重要 P1，重点展开机制、状态、边界和失败路径。
- **面试**：在正常笔记后按需增加高频问题与自测，不把问答重复成第二篇笔记。
- **源码角度**：仅依据可靠源码说明入口、调用链、数据结构、并发或错误路径，不凭记忆编造名称和版本细节。

## 按需加载

普通、资料清晰的笔记直接按本文件执行，不要读取全部参考材料。

- 输入很长、噪声多或核心难以取舍时，读取 [references/core-extraction.md](references/core-extraction.md)。
- 用户强调 5W1H、章节映射或适用边界时，读取 [references/5w1h-framework.md](references/5w1h-framework.md)。
- 长文需要统一中文表达或消除 AI 腔时，读取 [references/chinese-writing.md](references/chinese-writing.md)。
- 用户要求深入、面试、源码视角，或内容依赖版本与外部证据时，读取 [references/deep-dive.md](references/deep-dive.md)。
- 笔记较长、主题复杂或用于正式沉淀时，读取 [references/quality-check.md](references/quality-check.md)。
- 需要完整结构起稿时，复制并按内容删减 [assets/note-template.md](assets/note-template.md)；不要为了套模板保留空章节。

## 输出约束

- 默认只输出最终 Markdown 笔记，不展示内部分级和筛选过程。
- 第一部分尽快建立核心心智模型，不从历史背景或泛泛介绍开始。
- 流程用编号列表，真实比较用表格，结构关系复杂时才使用 Mermaid。
- 示例用于解释机制或边界，通常一个即可；第二个只用于展示不同边界。
- 不大段复制来源，不用比喻替代机制，不在结尾机械复述全文。
