# 核心知识提取

在输入很长、噪声多、观点重复或信息取舍困难时读取本文件。

## 最小充分知识集合

### P0：必须保留

- 一句话定义与概念边界。
- 要解决的核心问题。
- 核心机制与关键因果链。
- 关键数据流或控制流。
- 会影响正确使用的边界条件。
- 会造成错误理解的反例或误区。

### P1：按目标保留

- 对理解机制必要的实现细节。
- 一个能建立心智模型的例子。
- 与常见替代方案的决策差异。
- 性能、一致性、复杂度、安全性或运维权衡。
- 典型工程用法，以及必要的源码、协议或配置细节。

### P2：默认省略

- 历史沿革、重复背景和边缘功能。
- 多个作用相同的例子。
- 不改变理解与决策的实现细节。
- 与主题关系较弱的延伸知识。
- 泛泛的行业描述和评价。

默认范围是全部 P0 加上与用户目标直接相关的 P1。原始资料越长，不代表笔记应同比增长。

## 删除测试

写入一条信息前询问：

> 删除它后，读者是否仍能正确解释机制、判断使用条件并避开关键误区？

- 会造成概念错误、因果断裂、条件缺失或工程判断失真：保留。
- 只损失背景趣闻、重复说明或相似例子：删除。
- 会丢失关键边界、失败条件、代价或反例：保留。

## 建立知识主干

不要沿原文目录缩写。先提取：

1. **对象**：核心实体是什么。
2. **关系**：实体如何关联。
3. **机制**：输入如何变成输出。
4. **因果**：为什么这样设计。
5. **状态**：什么发生变化，由谁维护。
6. **边界**：什么条件下成立或失效。
7. **权衡**：获得什么，付出什么。
8. **例外**：什么情况会打破直觉。

优先建立关系，再补细节。不要把“资料里出现过”当作保留理由。

## 建立因果链

优先表达：

`问题 → 约束 → 机制 → 结果`

对机制型知识检查：

- 输入是什么？
- 谁接收或处理输入？
- 中间状态存在哪里？
- 什么事件推动状态变化？
- 输出和错误路径是什么？

单独罗列事实只能说明“发生了什么”；长期笔记应尽量解释“为什么会这样表现”。

## 精华判定

满足以下任一条件时提高保留优先级：

- **解释力**：一条规律可以解释多个现象。
- **可迁移性**：可迁移到其他系统或场景，如背压、幂等、缓存失效、控制面与数据面分离。
- **决策价值**：会改变选型、使用时机、安全边界或性能判断。
- **机制价值**：能解释系统行为产生的原因。
- **边界价值**：揭示前置条件、失效条件、版本差异或并发与权限边界。
- **复习价值**：数周后能快速恢复心智模型。

只对某个版本或参数成立的细节，应标明适用范围并降低默认优先级。

## 压缩方法

- **删除**：主持句、空评价、重复定义、弱相关背景、无新信息的例子。
- **合并**：把回答同一问题的段落合并为一个知识单元。
- **上提**：先写可迁移规律，再保留一至三个最有解释力的证据。
- **替换**：把“灵活、强大、高效”等评价换成具体对象、动作、约束或结果。
