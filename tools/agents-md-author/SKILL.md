# AGENTS.md 编写

为 Codex 编写短小、准确、与目录作用域匹配的持久项目指令。保留真正会改变代理决策的约束，把场景化细节路由到按需读取的文档，避免让每个任务都承担无关上下文。

## 开始前

完整读取 [references/authoring-guide.md](references/authoring-guide.md)，再创建、修改、拆分或审查任何 `AGENTS.md` / `AGENTS.override.md`。该文件包含发现顺序、作用域、覆盖规则、路由写法和质量检查。

## 工作流

1. 查找从仓库根目录到目标文件所在目录之间适用的 `AGENTS.md` 与 `AGENTS.override.md`，确认现有指令链和冲突优先级。
2. 检查仓库中的真实命令、目录和约定；不要把猜测或一次性偏好固化为持久规则。
3. 判断内容应属于哪个载体：
   - 跨任务长期成立的仓库约束放入适用作用域的 `AGENTS.md`。
   - 仅限某个子树的约束放入该子树的 `AGENTS.md`。
   - 可复用的多步骤工作流放入 Skill。
   - 一次性要求留在当前提示词。
   - 详细但仅在特定场景需要的说明放入独立文档，并由 `AGENTS.md` 用明确条件路由。
4. 选择能覆盖目标文件的最窄合理作用域，优先修改已有文件；没有实际作用域差异时不要新增嵌套文件。
5. 采用最小修改，保留不冲突的现有约定。只有用户明确需要同目录完全覆盖时才使用 `AGENTS.override.md`。
6. 验证所有路径、命令和路由目标存在，检查上下层指令是否重复或冲突，并确认修改没有扩大用户授权。

## 输出原则

- 指令必须可执行、可验证，并说明触发条件或适用范围。
- 根文件只保留广泛适用的规则和简短路由；详细说明放在被路由文件中。
- 路由要写成“当发生 X 时，读取 Y”，不要只留下裸链接或假设 Codex 会自动加载普通 Markdown 文件。
- 不复制平台已经保证的通用能力，不添加泛泛的“写好代码”“仔细检查”等提醒。
- 不为凑结构创建空章节、占位文件或无实际差异的层级。
- 除非用户要求，不改动与本次目标无关的现有指令。

## 完成标准

- 指令放置位置与目录作用域一致。
- 根级常驻上下文保持精简，场景化细节可被准确发现。
- 更深层规则只覆盖必要部分，没有意外取消上层约束。
- 所有引用路径和命令均已核验。
- 最终说明修改了哪些指令层、为什么放在那里，以及如何验证。
